# Codex Kanban

**Codex Kanban 是为 Codex 做的原生项目看板插件。你可以在 Codex 里管项目、安排任务，也可以从卡片直接打开对应的会话。**

**单独启用自动更新，并把会话关联到卡片后，Codex 会把进展、下一步和任务状态写回看板。** 你可以直接在看板上了解每件事做到哪了，再进入会话继续工作。

事情是否做完，仍由你来确认。Codex 报告完成时，卡片会先进入“待验收”，等你在看板中确认后才算完成。

当前版本：**0.3.3-preview.1，测试版**。这是个人开发的开源插件，需要自行安装。目前只在 Mac 上做过测试，仍有功能和使用场景需要继续验证。

<img src="docs/images/card-guide-c.png" width="640" alt="纸感拼贴插画：人物整理看板上的任务卡，旁边的时钟与日历呼应跟进时间和交付计划。" />

一件事放在一张卡片里：现在做到哪了、接下来做什么、谁来跟进、什么时候交付。本文三张图都是说明用的插画，实际界面以插件为准。

## 平时怎么用

- **从卡片直接打开 Codex 会话。** 把已有会话关联到卡片，或新建一个会话来处理这件事。以后点击“打开会话 ↗”，就能回到对应会话继续工作。
- **让会话自动更新看板。** 先启用自动更新，关联的会话就能把进展、下一步和状态写回卡片。安装插件后，还需要单独完成这项设置。
- **按项目整理任务。** 可以用看板，也可以用表格。任务分为未开始、计划中、进行中、待验收、已完成和暂停。
- **记住谁跟进、什么时候交。** 跟进时间是下次问进展或推动事情的时间；计划交付日是希望交出成果的日期。“今天需跟进”会列出今天及此前该跟进的事，“逾期事项”会列出超过交付日的事。日期按北京时间计算。
- **把相关内容留在卡片里。** 检查清单、完成要求、遇到的问题、成果链接和修改记录，都可以跟着任务保存。最终是否完成，由你在看板中确认。

<img src="docs/images/session-model-c.png" width="640" alt="纸感拼贴插画：项目文件夹收纳任务卡，一张卡片与大小不同的会话气泡相连。" />

一个项目里可以放多张卡片。每张卡片可以关联一个主要会话，也可以加上几个协作会话；暂时没有会话的任务，也能先记在看板里。

## 点一下卡片，回到 Codex 会话

<img src="docs/images/native-session-c.png" width="640" alt="C 系列纸感拼贴概念插画：人物点击看板中的蓝色卡片，蓝色纸箭头直接通向同一应用内的会话区域，表达看板与 Codex 原生会话联动。" />

**点击卡片上的“打开会话 ↗”，Codex 就会直接切换到这张卡片关联的主要会话。** 插件里把这个主要会话叫作“主会话”，每张卡片最多关联一个。

你可以在会话里继续处理任务。**启用自动更新后，新的工作进展会写回同一张卡片。**

## 怎么安装

目前面向 Mac。电脑上需要有：

- 已安装并登录的 Codex 桌面应用。
- 官方 Codex 命令行工具（Codex CLI），用来执行下面的安装命令。
- Node.js 22.12 或更新版本，这是运行插件所需的软件。本次测试使用的是 24.20.0。

在 Mac 的“终端”中依次运行下面两行，把这个 GitHub 仓库加入 Codex，再安装看板：

```sh
codex plugin marketplace add HaosuStrasbourg/codex-kanban --ref main
codex plugin add codex-pm@codex-kanban
```

安装后，在 **Codex App → 插件 → Kanban 项目管理** 打开看板。更新后如果仍看到旧内容，先关闭看板再打开；仍没有变化时，再退出并重启 Codex。

<details>
<summary>下载到电脑后安装，或处理软件路径问题</summary>

仓库已带好安装文件，位于 `dist/codex-pm/`。也可以下载并解压仓库，在仓库根目录运行 `codex plugin marketplace add .`，再执行上面的安装命令。`main` 中的版本仍在测试，更新前请查看下方的测试说明。

插件会查找电脑上已有的 Node.js，不会替你下载或安装。常见 Mac 安装位置和 Homebrew 安装位置都在查找范围内。

如果 Node.js 或 Codex CLI 装在其他位置，需要在插件 MCP 的 `env` 配置中，用 `CPM_NODE_BIN`、`CPM_CODEX_BIN` 指明完整路径，然后重新加载插件。自动更新使用的 Hook 也需要相同配置。这里的 Hook 是让 Codex 在会话开始、结束或中断时通知插件的功能。

找不到合适的 Node.js 时，插件会报错；找不到 Codex CLI 时，项目和会话列表会显示不可用。

</details>

## 怎么让会话自动更新看板

**自动更新需要单独开启，安装完成并不代表已经开启。** 你需要选定允许更新的项目、完成会话通知的设置，再把会话关联到卡片。当前 Codex 版本也需要支持这项功能。

具体步骤见 [自动更新设置说明](docs/2026-10-11%20-%20自动同步配置.md)。设置好后，用一张测试卡片确认进展能写回来，再开始日常使用。

自动更新只处理你允许的项目，以及已经关联且所在目录相符的会话。插件不会读取历史聊天正文来补写进度，也不会保存完整聊天内容。你仍然决定任务是否完成。

## 数据放在哪里，怎么停用

看板数据保存在你的电脑上，不放在这个 GitHub 仓库中。

要停用，在 **Codex App → 插件** 中禁用看板；如果另外开启了自动更新，也要关闭对应项目的会话通知设置。重新启用同一个插件后，可以继续读取原来的数据，不需要删除数据文件。

如果之前安装过其他来源的测试版本，它们可能使用不同的数据位置。这个版本不会自动搬入旧数据。

<details>
<summary>查看数据位置、备份和恢复方法</summary>

数据文件位于 Codex 为插件提供的 `PLUGIN_DATA/kanban/kanban.sqlite`。手工设置 `CPM_DATA_DIR` 可以改用其他完整路径；没有这项需要时，保留默认位置即可。

需要备份或恢复时，先按下方开发说明安装所需软件包，再把命令中的示例路径换成自己的数据文件路径：

```sh
npm run cpm -- --db /absolute/path/kanban.sqlite backup /absolute/path/new-backup.sqlite
npm run cpm -- --db /absolute/path/kanban.sqlite restore /absolute/path/backup.sqlite --confirm
```

恢复会替换指定数据文件中的内容。操作前先停用插件和自动更新，并另存一份当前备份。

</details>

## 想自己改代码

<details>
<summary>查看开发命令和文件说明</summary>

下载源码后，在仓库根目录运行：

```sh
npm ci
npm run typecheck
npm test
npm run test:release
npm run build
npm run test:package
```

这些命令会安装所需软件包、检查代码、运行测试，再生成安装文件。发布时要一并保留 `dist/codex-pm/`，Codex 会从这个目录安装插件。

| 目录 | 内容 |
|---|---|
| `packages/core` | 数据保存、修改和权限规则 |
| `packages/server` | 插件工具，以及读取项目和会话信息的代码 |
| `packages/hooks` | 接收会话通知，检查哪些项目可以自动更新 |
| `packages/ui` | React 看板与详情 |
| `plugin` | 插件声明、启动器、技能和图标 |
| `.agents/plugins/marketplace.json` | 插件源清单 |
| `dist/codex-pm` | 生成好的插件安装文件 |

</details>

## 目前还有哪些没测完

这个版本已经做过代码和安装文件检查，但还没有测完所有使用场景。其他电脑上的安装、会话自动更新和长时间使用是否稳定，都需要继续验证；Windows 和 Linux 也没有测试过。

**目前请在看板里确认完成和勾选完成要求，不能直接在会话里代替这一步。**

<details>
<summary>查看具体测试范围和数量</summary>

这个公开仓库保留源码和代码测试，不包含个人数据、真实聊天记录、历史运行记录、安装备份或早期试验文件。因此，运行这里的 `npm test`，不等于检查了原开发项目的全部使用场景。

原开发项目共有343项使用场景检查，最近一次完整记录通过244项。其中，必须优先解决的问题（P0）通过111/139项，其他问题（P1/P2）通过133/204项。目标是P0全部通过，P1/P2至少90%通过，目前尚未达到。这些是原开发项目的历史记录，不是本公开版本的新成绩。

本公开版本实际做过哪些检查，见 [测试记录](docs/2026-10-11%20-%20预览验证.md)。其中部分测试使用示例数据和模拟环境，不能据此认定另一台电脑上的 Codex 已经使用正常。由不同模型实际执行任务的测试，以及长时间使用检查，也还没有完成。

</details>
