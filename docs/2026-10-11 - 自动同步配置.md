# 自动同步配置

**安装插件、项目范围许可、Hook 注册和信任是四个独立步骤。** 当前开发预览不自动修改 Codex 配置；没有完成后续配置时，看板可以使用，自动报告会显示尚未接通。

1. 在 Codex App 打开看板，登记准确项目并获取其项目 ID（可通过插件 `cpm_snapshot` 核对）。只选择用户明确批准的项目。
2. 确认该插件真实的 `PLUGIN_DATA/kanban` 目录。不要猜缓存路径，不要复用别的插件或旧测试市场的数据目录。首次打开看板会创建此目录。
3. 经用户确认后，在该目录写入 `hook-scope.json`，权限0600、目录权限0700，普通文件且无符号链接。内容如下，示例 ID 必须替换为核对过的真实项目 ID：

```json
{"mode":"bound-sessions","projectIds":["YOUR_CONFIRMED_PROJECT_ID"]}
```

4. 在 Codex App 检查本插件的5类 Hook：SessionStart、UserPromptSubmit、PreToolUse（仅匹配 `mcp__codex_pm__cpm_report`）、Stop、Interrupt。逐项审阅并信任。注册模板位于 `dist/codex-pm/hooks/hooks.json`。
5. 某些 Codex 版本不会从 portable plugin 自动加载 Hook。若未发现，先核对该版本的官方 Hook 配置文档，再由用户批准合并到项目 `.codex/hooks.json`。保留已有 Hook；将模板中的 `PLUGIN_ROOT` 换为安装插件的准确绝对路径，并为每条命令明确指定同一个 `CPM_DATA_DIR`（第2步确认的 `kanban` 目录）。项目 Hook 不一定有插件的环境变量，不能原样复制后假定可用。不要从 AI 工具或任意 shell 输入绕过信任。
6. 重新加载会话后，用一张不含私密内容的测试卡绑定测试会话。真实发送两轮消息，再做一次中断，检查进展、活动、待补同步和人工验收边界。只有实际报告写入成功才算接通；configured、trusted 或命令存在都不是充分证据。

安全边界：范围不匹配、无有效回合、缺少可信会话身份时拒绝报告。不会读取历史聊天正文补进度；不会由会话结束自动确认完成。其他项目及未绑定会话不会因这份范围许可变成已绑定。

关闭同步：由用户禁用对应项目 Hook，并移除或停用这份范围许可；保留数据库。升级改变命令时可能需要重新信任。跨平台、其他宿主版本以及全新账号的完整流程尚未验证，问题请附脱敏错误信息，不要上传数据库或聊天记录。
